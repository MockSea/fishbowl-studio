Fishbowl Studio desktop app 0.1.0: QA

Fishbowl Studio 0.1.0 is the Electron desktop app that drafts social posts for a brand with Claude, using the owner's own Anthropic API key. This report walks every screen and flow on main at 10857ce, from source and from the packaged macOS app. The core works in both: key storage, setup, drafting from a link, the brand kit's file checks, a second persona, and state surviving a restart. The bugs are a brand kit that accepts the same file twice and says nothing about the good file in a mixed drop, and leftover wording from the Claude plugin that does not match the desktop app.

Each run gets its own empty data and app folders, so the owner's real data is never touched. No real API key was used: a local mock (dev/mock-anthropic.mjs) answers drafting calls, a local server that refuses every request stands in for a bad key and for rate limiting, a closed port stands in for no network, and one call goes to the real Anthropic API with a made-up key. Brand kit files are dropped through Chromium's own drag and drop events, so the page receives real files with paths, the way a Finder drag delivers them. Fixtures are generated at run time and describe a fictional bike shop.

Bugs (10)

medium

B1. The brand kit accepts the same file twice, and both copies go to Claude

Brand kit

Steps

  1. Open Brand kit.
  2. Drop brand-guidelines.pdf.
  3. Drop brand-guidelines.pdf again (alone or with other files).

Expected

The second drop is refused or replaces the first, with a message such as "brand-guidelines.pdf is already in the kit".

Actual

The kit lists brand-guidelines.pdf twice, and the next drafting request carries both copies (the mock logged 4 documents for 3 distinct files), so every draft pays for the duplicate text.

Where

desktop/brandkit.js add(): no check against the names or contents already in manifest.json

Seen in: From source (npm run desktop); Built .app, launched with Finder's PATH

medium

B2. A drop with one good and one bad file reports only the bad one

Brand kit

Steps

  1. Open Brand kit.
  2. Drop a PDF and a GIF together.

Expected

One message that says the PDF was added and the GIF was not, with the reason.

Actual

The only message is "animation.gif: Only .pdf, .docx, ... files." The PDF is added silently. Someone who reads the error and drops the PDF again gets a duplicate (B1).

Where

desktop/ui/desktop-pages.js addFiles(): the success message is shown only when nothing failed

Seen in: From source (npm run desktop); Built .app, launched with Finder's PATH

B3. The setup message after "Draft it for me" is written for a tool, not a person

Setup

The text returned by the setup-drafts tool, shown as the flash by the desktop host

What passed

  • Both launch modes start and show every screen: Drafts, Sources, Topics, Brand kit, Schedule, Settings, Reads, Playbook. The Coach page is gone, as intended.
  • The packaged app runs from its own binary with launchd's PATH (/usr/bin:/bin:/usr/sbin:/sbin), so it needs no node. PDF and DOCX text extraction works there too.
  • API key: empty, short, spaced and odd-character keys are refused with a plain message. A good key is saved encrypted (mode 600) in the app folder, the plain key appears in no file, the page only ever sees a masked hint, and Remove key deletes it.
  • No key: Ask Claude now, Run it now and Draft it for me each say to add the key under Settings; a link is still queued for later.
  • Bad key (401), rate limit (429), no network, and the real Anthropic API with a made-up key each give a plain message. No network fails in about 4 seconds.
  • Setup with the mock API: Draft it for me, Keep everything and Finish setup work and use the brand name from step 1.
  • Draft from a link with Ask Claude now produces three takes; Use this one and Approve work.
  • Brand kit: PDF, DOCX, Markdown, PNG and JPEG are added and their text previewed. Refused with a clear reason: a PDF over 10 MB, an image over 5 MB, a text file named .pdf or .png, a broken DOCX, a DOCX that unpacks to 70 MB, a scanned PDF, an empty file, a GIF and an .exe. Choose files works. Remove asks once more, then removes. The next drafting call carries the kit's documents and images.
  • A second persona gets its own empty brand kit, shares the API key, and switching back shows the first brand's kit.
  • The Run on its own switch is saved to the app's preferences and survives a restart. A topic can be added. No sideways scroll at the 900 x 600 minimum window.
  • Quit and relaunch keep the key, the active brand, the kit, the switch and the drafts. Closing the window keeps the app running, and the Dock icon brings the window back.

Not tested

  • A double-click in Finder by hand. The built-app run uses the packaged binary with Finder's PATH, which covers the no-node case; finder.mjs (opened through LaunchServices) is written but was not run in this pass.
  • The keychain prompt a signed or notarised build would show, and Gatekeeper on another Mac. The build is unsigned (identity null), so another Mac will refuse to open it without a right-click Open.
  • Real drafting quality. Every successful drafting call went to the mock, whose drafts all mention "Draft 1", which is why the drafts carry a "Check the number" flag.
  • The timed run while the app stays open (the switch was checked, a real scheduled batch was not waited for).
  • Windows and Linux builds.

How to rerun

npm ci and npm run make at the repo root (the built-app runs need dist/), then cd test/e2e, npm ci, npm run qa. npm run qa:source, qa:built and qa:finder run one part. QA_REAL_API=0 skips the single call to the real Anthropic API. The scripts exit at once unless STUDIO_E2E=1, so the repo's own npm test never launches the app.
