Fishbowl Studio desktop app 0.1.1: QA

Fishbowl Studio 0.1.1 fixes nine of the ten bugs in the 0.1.0 QA report. Each bug has a check in the end-to-end walk (and, for B1, B3 and B4, a unit test) that failed against 0.1.0 and passes now, from source and from the packaged app. B6, the Topics link to the Coach page, is left for WS-106 and stays in the suite as a known failure. Each fixed bug below shows its checks before and after and a screenshot from each run.

Before: Built .app, opened by LaunchServices (open)Not run. finder.mjs was run after the fixes only. Its one failure is about this test machine, not the app: launchd's PATH here includes Homebrew, so the run cannot show a launch with no node on PATH. The built-app walk covers the no-node case with Finder's PATH.

Each run gets its own empty data and app folders, so the owner's real data is never touched. No real API key was used: a local mock (dev/mock-anthropic.mjs) answers drafting calls, a local server that refuses every request stands in for a bad key and for rate limiting, a closed port stands in for no network, and one call goes to the real Anthropic API with a made-up key. Brand kit files are dropped through Chromium's own drag and drop events, so the page receives real files with paths, the way a Finder drag delivers them. Fixtures are generated at run time and describe a fictional bike shop. The before runs used the 0.1.0 code at 4bea5d3 with the new checks, from source and from a packaged build of that commit. The after runs used the same scripts on the fixed code and a fresh build.

B1. The brand kit accepts the same file twice, and both copies go to Claude

Brand kit

What was wrong

The kit lists brand-guidelines.pdf twice, and the next drafting request carries both copies (the mock logged 4 documents for 3 distinct files), so every draft pays for the duplicate text.

Fix

The kit refuses a file whose name is already in it (any case) and a file whose contents match one already in it, with the name of the copy it matches. Each manifest entry now records a sha256 of the stored file; entries from older kits are hashed on demand.

Files: desktop/brandkit.js

B5. "How this works" on Drafts describes the plugin: a scheduled task, four steps and posting

Drafts

What was wrong

Step 1 says "Four short steps: the brand, a few questions, Claude's drafts for you to keep or change, and whether it posts for you." Step 3 says "One click asks Claude to make the scheduled task." The app's setup has three steps, cannot post, and has no scheduled task.

Fix

The shared board takes its first-run step text through a firstRunSteps hook. The desktop app supplies three setup steps with no posting, and a schedule step that says the app drafts on that schedule while it is open. The wizard counts its steps (three on the desktop) instead of saying of 4.

B10. A renamed first brand keeps the handle @my-brand

Personas

What was wrong

Every draft and the switcher show "Spoke and Chain @my-brand". A second brand made with Add persona gets @night-market-bakery.

What passed

  • Both launch modes start and show every screen: Drafts, Sources, Topics, Brand kit, Schedule, Settings, Reads, Playbook. The Coach page is gone, as intended.
  • The packaged app runs from its own binary with launchd's PATH (/usr/bin:/bin:/usr/sbin:/sbin), so it needs no node. PDF and DOCX text extraction works there too.
  • API key: empty, short, spaced and odd-character keys are refused with a plain message. A good key is saved encrypted (mode 600) in the app folder, the plain key appears in no file, the page only ever sees a masked hint, and Remove key deletes it.
  • No key: Ask Claude now, Run it now and Draft it for me each say to add the key under Settings; a link is still queued for later.
  • Bad key (401), rate limit (429), no network, and the real Anthropic API with a made-up key each give a plain message. No network fails in about 4 seconds.
  • Setup with the mock API: Draft it for me, Keep everything and Finish setup work and use the brand name from step 1.
  • Draft from a link with Ask Claude now produces three takes; Use this one and Approve work.
  • Brand kit: PDF, DOCX, Markdown, PNG and JPEG are added and their text previewed. Refused with a clear reason: a PDF over 10 MB, an image over 5 MB, a text file named .pdf or .png, a broken DOCX, a DOCX that unpacks to 70 MB, a scanned PDF, an empty file, a GIF and an .exe. Choose files works. Remove asks once more, then removes. The next drafting call carries the kit's documents and images.
  • A second persona gets its own empty brand kit, shares the API key, and switching back shows the first brand's kit.
  • The Run on its own switch is saved to the app's preferences and survives a restart. A topic can be added. No sideways scroll at the 900 x 600 minimum window.
  • Quit and relaunch keep the key, the active brand, the kit, the switch and the drafts. Closing the window keeps the app running, and the Dock icon brings the window back.

How to rerun

npm ci and npm run make at the repo root (the built-app runs need dist/), then cd test/e2e, npm ci, npm run qa. npm run qa:source, qa:built and qa:finder run one part. QA_REAL_API=0 skips the single call to the real Anthropic API. The scripts exit at once unless STUDIO_E2E=1, so the repo's own npm test never launches the app. To repeat the before runs, check out 4bea5d3 with the new checks, build it, and run with QA_OUT=../../docs/qa/electron-0.1.1/before/shots and QA_APP pointing at that build.
